# Полные WXF-результаты и табличные Parquet

Дополнение `native-artifacts-v1` не меняет `compute-v1` и `closed-block-v1`. До подготовки native deployment проверьте `GET /api/compute/v1/capabilities`: `native_artifacts.protocol` должен быть `native-artifacts-v1`, а `formats` содержать требуемые форматы. Отсутствующее поле означает неподтверждённую поддержку. Не подавайте задание, полагающееся на эти гарантии, только потому, что helper присутствует в локальном клиенте; сначала нужен принятый серверный выпуск.

## Разные продукты одного прогона

Реестр storage/result форматов: `parquet`, `wxf`, `mx`, `wdx`,
`expressionjson`, `wlnet`, `wmlf`. WXF — основное переносимое представление
полного выражения; MX требует `compatibility` с версией Wolfram, SystemID и
разрядностью. Сервер хранит opaque форматы без выполнения. Не объявляйте SHA
или проверку заголовка доказательством semantic restore. Описание форматов
и пользовательских native datasets находится в [инструкции данных](../../wolfram-server-datasets/references/typed-formats.md).

- WXF сохраняет полный нативный объект Wolfram: вложенные структуры, комплексные и высокоточные значения, большие трассы. Сервер не заменяет его JSON или CSV и не десериализует произвольный объект ради предпросмотра.
- Parquet хранит явно выбранную таблицу с известными типами, единицами и политикой точности. Это может быть производное подмножество полного WXF, а не равнозначная копия. Научную схему и преобразование определяет автор расчёта.
- Для каждого файла фиксируются размер, SHA-256, формат, назначение, блок и происхождение. Если для результата обязательны оба формата, оба объявляются `required: true` и входят в проверяемую копию результата.

## Декларации перед запуском

В неизменяемом `config/config.json` добавьте явный перечень. Пути не содержат шаблонов или абсолютных имён:

```json
{
  "native_artifacts": {
    "schema_version": 1,
    "items": [
      {
        "block_id": "b1", "name": "trajectory",
        "path": "artifacts/b1/trajectory.wxf",
        "format": "wxf", "kind": "full-native-result",
        "required": true, "max_bytes": 104857600
      },
      {
        "block_id": "b1", "name": "observables",
        "path": "artifacts/b1/observables.parquet",
        "format": "parquet", "kind": "tabular-analysis",
        "required": true, "max_bytes": 10485760
      }
    ]
  }
}
```

Размеры — иллюстрация формы контракта. Выбирайте их по измерению задачи. `required_free_bytes` должен покрывать не менее удвоенной суммы объявленных `max_bytes`: во время закрытия существуют draft и независимая опубликованная копия. Дополнительно учтите остальные результаты и рабочее место задачи.

Native-пакет включает `sdk/compute_client/native_artifacts.py` и `sdk/compute_client/data_formats.py` как `instrumentation`; Wolfram-пакет также включает `runners/wolfram/NativeArtifacts.wl` как `instrumentation`. Обычные runner и обязательные SDK-файлы сохраняются.

## Экспорт и закрытие блока

Python-задача получает разрешённый draft path через `compute_client.native_artifacts.artifact_path(block_id, name)`. Экспортируйте данные явно, завершите запись и закройте файл до возврата из `compute_block`.

Для Wolfram доступны `QWNativeArtifactPath[blockID, name]` и `QWExportNativeArtifact[blockID, name, expression]`. Второй helper экспортирует в явно объявленный для этого артефакта формат, если он доступен в `$ExportFormats`. Parquet создаёт явно выбранный exporter с научной схемой; helper не угадывает колонки и не снижает точность.

В новых версиях Wolfram документирован [экспорт Parquet](https://reference.wolfram.com/language/ref/format/Parquet.html). Перед выбором этого пути проверьте установленную версию, наличие формата в `$ExportFormats` и фактическое чтение полученного файла независимым Parquet reader. Поддержка формата в актуальной документации не подтверждает его доступность в конкретной среде. Для комплексных и произвольной точности величин заранее задайте представление табличной части; полную структуру и точность сохраняйте в WXF.

После возврата science-функции runner публикует копию закрытого draft в отдельный inode, проверяет размер и SHA и фиксирует `artifacts/manifest.json`. Worker независимо проверяет обязательные результаты до принятия checkpoint и перед `compute_complete`. Пропущенный обязательный WXF или Parquet означает ошибку, а не частичный успех.

Возвращаемые `compute_block` / `QWComputeBlock` записи сохраняют контракт `closed-block-v1` и его явное `expected_records`. Полный nested/complex/high-precision объект записывается отдельно в WXF; не пытайтесь дополнительно протолкнуть его целиком через JSON/CSV checkpoint или ответ MCP. Состав небольших записей и табличных наблюдаемых должен соответствовать постановке владельца, а не выбираться адаптером автоматически.

## Адаптер Wolfram и длительный блок

`QWComputeBlock[configuration, block]` — точка входа профиля `wolfram_closed_block_v1`. Runner загружает `science/task.wl`, затем вызывает эту функцию для каждого объявленного блока. Адаптер вызывает существующие научные функции в том же kernel и задаёт серверные пути записи; математическая модель, точность и критерии остаются заданными владельцем.

Схема интерфейса ниже предполагает реальную функцию `ExistingScientificCalculation[configuration, block]`, которую предоставляет автор задачи. Это не готовая научная задача: прежде чем применять схему, сопоставьте имя, параметры и возвращаемое значение существующего алгоритма. Проверка определения останавливает шаблон без научной реализации.

```wolfram
QWComputeBlock[configuration_Association, block_Association] := Module[{result},
  If[DownValues[ExistingScientificCalculation] === {},
    QWFail["science_entrypoint_not_defined"]];
  result = ExistingScientificCalculation[configuration, block];
  If[result === $Failed || FailureQ[result], QWFail["science_calculation_failed"]];
  QWExportNativeArtifact[block["id"], "trajectory", result];
  {<|"block_id" -> block["id"], "result_format" -> "wxf"|>}
];
```

Для каждого блока заранее объявите required-артефакт `trajectory` в формате `wxf`, его путь и измеренный `max_bytes`. Пример возвращает одну небольшую checkpoint-запись на блок; `expected_records` и научная схема должны соответствовать фактическим записям. Если алгоритм уже пишет файл, передайте ему `QWNativeArtifactPath[block["id"], "trajectory"]`, завершите запись и верните запись только после закрытия файла.

Один длительный содержательный блок допустим, когда расчёт неделим по исходному методу. Работа продолжается без соединения с агентом. До завершения блока доступна in-block telemetry, но нет подтверждённого checkpoint этого блока; при потере kernel незавершённый блок повторяется целиком. Snapshot произвольного состояния kernel автоматически не создаётся. ETA и процент без достаточных измерений остаются неизвестными.

Блоки одного job выполняются последовательно в одном kernel. При resume новая попытка пропускает уже закрытые блоки: следующий блок должен получать зависимости из immutable inputs или опубликованных файлов, а не только из глобальных переменных предыдущего kernel. Математическое разбиение непрерывной эволюции нельзя придумывать ради удобства checkpoint. Три параллельных kernel обслуживают независимые jobs в общем бюджете пула.

Перед переносом standalone-скрипта проверьте `Exit[]`, очистку `Global`-контекста, абсолютные Windows-пути, загрузку модулей и самостоятельную запись outputs. Его научные функции должны вызываться в выделенном kernel; вложенный запуск ещё одного `wolframscript` требует дополнительного ресурсного и лицензионного бюджета. Приёмка платформенного адаптера на синтетике не заменяет smoke конкретного кода, controlled Import и существующую научную QA.

## Входной бюджет и рабочее место

На `wolfram-server.ru` 28.10.2026 установлены `max_bundle_bytes = max_unpacked_bytes = max_file_bytes = 1073741824`; datasets `max_source_bytes` также равен 1 ГиБ. Актуальные capabilities проверяйте заново перед передачей. Для bundle учитывайте все файлы и ZIP overhead; источник ровно 1 ГиБ подходит под отдельный datasets source budget, но вместе с кодом превышает общий bundle budget. Источник меньшего размера также требует проверки итогового размера пакета.

Повышение лимита проверено на границах metadata admission; реальная передача 0,8 ГБ и RAM после `Import` этим не подтверждаются. Фактический memory peak, место для immutable inputs, drafts и независимой публикации outputs измеряются отдельно. Общий бюджет памяти пула остаётся 5 ГиБ и распределяется между Python/Wolfram jobs; свободные три слота не означают возможность трёх тяжёлых imports одновременно.

Существующий `finalize-compute.py` работает после `compute_complete`. Поэтому он подходит для дополнительного производного dataset, но не может создавать Parquet, который объявлен обязательным условием достижения `compute_complete`.

## Получение результата

`artifact_manifest` / `compute_artifact_manifest` возвращает только метаданные и opaque artifact IDs. Обычные `artifacts`/`fetch` сохраняют совместимость. Бинарные файлы не передаются текстом через MCP и не загружаются в контекст модели.

Типизированная подача `POST /api/compute/v2/try-submit` / `compute_try_submit_typed`
требует `result_formats`: точного набора форматов required declarations данного
deployment, без дубликатов и без значения по умолчанию. Несовпадение отклоняется
до создания задания. Порядок списка незначим. Это не изменяет научный код,
exporter или список результатов; конкретный файл одного из произведённых
форматов выбирается при получении.

Большой файл скачивается отдельным процессом через `scripts/compute-artifact-download.py`. Передавайте путь к закрытому credential-файлу, `job_id`, `artifact_id`, ожидаемые размер/SHA и явные ограничения объёма и времени. Актуальные обязательные параметры берите из `--help`. Возобновление допускается только с `--resume` и совпавшими метаданными `.part`; после загрузки проверяется SHA сохранённого файла, затем выполняется атомарное закрытие результата.

При получении обязательно укажите `--format` / `expected_format`; сервер сверяет
его с неизменяемым объявлением до выдачи байтов и возвращает `X-Data-Format`.
В HTTP используются `Range`, `Content-Range`, `ETag`/`If-Match`. Обрыв сети не требует повторного расчёта. Несовпадение формата, размера или SHA запрещает использование копии как готового результата.

## Проверка копии

Совпавший SHA подтверждает точные байты. Для принятия полного восстановления отдельно выполните чтение Parquet с проверкой схемы/точных значений и контролируемый Wolfram `Import` WXF с проверкой ожидаемой структуры и точности. Не выполняйте произвольные сторонние WXF как доверенный научный код. В копию прогона включаются оба обязательных формата и manifest; библиотека, секреты и исполняемая среда имеют отдельные контуры резервирования.
