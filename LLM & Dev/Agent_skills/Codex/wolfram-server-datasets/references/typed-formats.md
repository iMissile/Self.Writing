# Типизированные версии данных

Используйте `GET /api/datasets/v2/capabilities` для проверки серверного выпуска.
Отсутствующий маршрут или формат не заменяйте предположением по наличию SDK.

## Формат передачи и хранения

`source_format` и `storage_format` обязательны при начале upload. Для CSV
разрешена только явно объявленная таблица Parquet с заданной схемой и политикой
точности; Parquet сохраняется как Parquet. Native версии сохраняют точные байты
в одном из форматов `wxf`, `mx`, `wdx`, `expressionjson`, `wlnet`, `wmlf`.
Переименование расширения не является преобразованием.

Идентичность версии: `dataset_id`, `version`, описание, provenance, исходные
`source_sha256` и `source_bytes`, явный `reservation_bytes`. Для таблицы нужны
колонки, единицы, точность и nullable; для native — `native_descriptor` с
объявленной структурой. Не выводите физический смысл из формата файла.

MX требует `compatibility` с точными `wolfram_version`, `system_id` и
`system_word_length`. Другие native форматы также могут сохранять сведения
о среде. Они не являются доказательством совместимости произвольной структуры.

## Передача

На узле `wolfram-server.ru` 28.10.2026 источник допускается до `1073741824` байт (1 ГиБ) включительно. Проверяйте фактический `max_source_bytes` в capabilities; на другой машине или при последующей настройке значение может отличаться. Параметр `--max-bytes` transfer-клиента выбирайте явно не ниже размера собственного файла и в пределах принятой политики. Серверная квота и резерв дополнительно покрывают metadata; предел отдельного source не увеличивает автоматически общий бюджет хранения или память вычислительного задания.

Начало upload возвращает непрозрачный handle. Бинарные блоки передаются через
`scripts/dataset-transfer.py --api-version 2 --format <source_format>` с явными
лимитами; актуальные флаги проверяйте по `--help`. Запускайте клиент через `uv`.
Каждый запрос содержит `expected_source_format`, связанный с upload handle.
После сетевой неопределённости сверяйте offset и исходный SHA, не создавайте
вторую версию вслепую. Идемпотентность finalize проверяйте по receipt именно
этого handle, версии и полного spec.

При получении файла задавайте `expected_format` сохранённого payload. Совпадение
формата проверяется до выдачи байтов. `scripts/dataset-download.py` скачивает
файл вне контекста модели, с явными SHA/размером/бюджетами; возобновление
привязано к dataset/version/формату. Несовпадение формата запрещает выдачу;
сервер не создаёт другой формат автоматически.

## Чтение и проверка

Каталог возвращает записанные metadata и размеры без перечитывания гигабайтов
данных; `payload_sha256_verification=deferred_to_read` сообщает об этом явно.
Бинарное чтение проверяет фактические байты. Native schema описывает структуру
как объявленные metadata; табличный preview для native не поддерживается.

WXF сохраняет выражения, включая вложенные структуры и числа высокой точности.
MX — сериализация с ограничениями совместимости; WDX и ExpressionJSON — другие
представления выражений; WLNet и WMLF предназначены для моделей Wolfram.
Ни один storage upload не выполняет содержимое. Application-level восстановление
требует отдельной контролируемой проверки в подходящей среде. Чтение Parquet,
успешная десериализация и научная приёмка являются отдельными результатами.

При использовании данных в следующем вычислении фиксируйте dataset/version,
storage SHA, формат и совместимость в карточке и immutable inputs задания.
Не подменяйте полную WXF-структуру небольшим preview или выборкой Parquet.
