# Инициализация проекта разработки отчётов

Правила устройства репозитория, в котором исследовательский отчёт — изделие,
а не скрипт. Документ обезличен: подставляйте своё имя проекта, свой предмет.

**Правило без основания не удерживается.** Каждое соглашение здесь выросло из
наблюдения: молчаливого расхождения, пустого холста, числа, которое нельзя было
пересчитать. Основание называется рядом с правилом. Соглашение без основания
через полгода снимут как произвол — и будут правы.

---

## Инварианты

Двенадцать правил, нарушение которых означает, что устройство сломано, а не
что случай особый.

1. **Ссылки идут только вверх.** Ядро → предметный слой → лаборатория → отчёты.
   Ядро импортируется в пустом окружении, без лаборатории на пути.
2. **Расчёт живёт в библиотеке, не в чанке.** Пока алгоритм в чанке, проза и
   вычисление — две сущности, и они расходятся молча.
3. **Числа в прозе не пишутся.** Проза не пересчитывается.
4. **Перечни строятся из модели, а не набираются руками.**
5. **Прогоны не перезаписываются.** Имя каталога — момент расчёта и объект.
6. **Пустой результат пишется файлом** с объявленной схемой. Отсутствие файла
   неотличимо от «это не считали».
7. **Молчаливая деградация запрещена.** Ненайденное объявление — исключение
   с именем файла и ключа, а не значение по умолчанию.
8. **Имена колонок латиницей.** Русские подписи — только на слое вывода.
9. **Один отчёт — один графический движок.** Смешение читается как разный смысл.
10. **pandas не является слоем обработки.** Polars → Arrow → DuckDB напрямую.
11. **Пороги — параметры прогона, не свойства предмета.** Они в манифесте.
12. **Правило без исполнителя — намерение.** У каждого правила либо инструмент,
    либо исключение в библиотеке.

## Порядок инициализации

Восемь шагов. Каждый оставляет проверяемый след; не переходить дальше, пока
предыдущий не запускается.

### 1. Каркас

```
<project>/
├── AGENTS.md                как принимаются решения
├── README.md                что это и как запустить
├── render_all.md            полный прогон по шагам
├── pyproject.toml
├── docs/
│   ├── algorithm.md         что считает и почему так
│   ├── conventions.md       где что лежит
│   ├── tech_conventions.md  чем собираются отчёты
│   └── handover.md          состояние дел
├── plans/                   датированные планы работ
├── <core_pkg>/              ЯДРО — устанавливаемый пакет
├── portable.py              CLI поверх ядра, без Quarto
├── lab/
│   ├── paths.py             корни на машине — единственное при переносе
│   ├── lib/                 config, model, render
│   ├── model/               предметный слой, JSON
│   ├── tools/               validate_model, render_smoke, diff_runs
│   ├── insights/            датированные наблюдения
│   ├── *.qmd                отчёты
│   ├── _artifacts/          ПРОГОНЫ (вне git)
│   ├── _cache/              кэши (вне git)
│   └── _ai_temp_scripts/    песочница (вне git)
└── tests/
```

Каталоги с подчёркиванием — вне git: прогоны и кэши восстанавливаются запуском.
Черновики разведки — только в `_ai_temp_scripts/`, не рядом с кэшем: мусор
у кэша однажды удалят вместе с кэшем.

Шаблон — `assets/docs/`. Границы слоёв и что где не должно лежать —
`references/layers.md`.

### 2. Окружение и зависимости

Python 3.13, `uv`, единое `.venv` в корне, запуск через `uv run`.
Исключение: `quarto render` не идёт через `uv run` — перед полным рендером
активировать окружение.

Взять `assets/pyproject.toml.template`. Каждая неочевидная зависимость несёт
комментарий «почему она». Полный разбор состава и запретов —
`references/stack.md`.

**Windows: UTF-8 в CLI.** Консоль по умолчанию cp1251; инструмент с `print("→")`
или таблицей Polars падает после расчёта. В начале `main()` каждого
`lab/tools/*.py` — `stdout`/`stderr.reconfigure(encoding="utf-8")` (с `hasattr`).
Не полагаться только на `$env:PYTHONIOENCODING` или профиль PowerShell.
Подробно — `references/tooling.md`, раздел «Консоль Windows и UTF-8».

### 3. `paths.py` — единственная точка переноса

Корни данных и артефактов в одном модуле. Ни один другой файл не знает путей
к машине. Шаблон — `assets/lib/paths.py`.

### 4. Предметный слой в JSON

Модель объявляет **знание**, а не настройку. У каждого объявления поле `why`;
замер живёт рядом в `measured` с датой; гипотеза объявлена гипотезой через
`status`. Устройство и правила — `references/model_as_data.md`.

### 5. Библиотека отрисовки

`lab/lib/render.py`: таблицы, карточки, графики, `inject_css(engine=...)`,
явный `show()`. Готовый скелет с обоими графическими стеками —
`assets/lib/render.py`. Он рабочий: движок — параметр, второй вендор
в одном документе даёт исключение.

Контракт вывода в HTML, почему он именно такой, и различия ECharts/Plotly —
`references/html_output.md`. Прочитать до первой строки кода отрисовки:
там четыре наблюдения, каждое из которых стоило пустого холста.

### 6. Прогоны и манифест

`save_run()` пишет датированный каталог с `run_manifest.json`. Устройство
манифеста, правила дозаписи, кэши — `references/runs.md`.

### 7. Инструменты

Минимум четыре: `validate_model.py`, `render_smoke.py`, `diff_runs.py`,
`pytest`. Что каждый ловит и почему без них правила не держатся —
`references/tooling.md`. Скелеты — `assets/tools/`.

### 8. Первый отчёт

`.qmd` самодостаточен: шапка целиком внутри файла, `_quarto.yml` не заводится —
так отчёт переносится и рендерится поодиночке. `embed-resources: true`.
Стек графики выбирается здесь и не меняется внутри файла.

Проверка готовности каркаса: `render_smoke` проходит на отчёте, который
рисует одну таблицу и один график, и падает, если попросить второй движок.

Шаблоны в `assets/` — рабочие, не иллюстративные:

| файл | что даёт |
|---|---|
| `assets/pyproject.toml.template` | состав с комментариями «почему она»; стек B закомментирован до первого потребителя |
| `assets/lib/paths.py` | единственная точка переноса, ошибка называет, где искали |
| `assets/lib/runs.py` | прогон, манифест, дозапись, баланс шагов |
| `assets/lib/render.py` | таблицы и **оба графических стека**; движок — параметр, второй даёт исключение |
| `assets/tools/render_smoke.py` | исполняет чанки и ловит два движка в одном файле |
| `assets/tools/validate_model.py` | объявление без `why`, гипотеза без замера, замер без даты |
| `assets/tools/diff_runs.py` | разность манифестов, предупреждение о неподключённой правке |
| `assets/docs/report_template.qmd` | шапка, setup с объявлением движка, пустая витрина |
| `assets/docs/AGENTS.md.template` | границы полномочий и обязательный цикл |

Ревизия чужого проекта по этим правилам: пройти инварианты сверху вниз,
на каждом назвать файл, где правило нарушено, и наблюдение, которым правило
обосновано. Не переписывать чужое устройство, если оно решает ту же задачу
другим способом и у него есть основание.

## Что этот скилл не решает

* **Предметную методику.** Правила касаются устройства, а не того, верен ли
  расчёт. Пройденный валидатор означает, что модель не противоречит себе.
* **Выбор между Quarto и другим сборщиком.** Здесь предполагается Quarto;
  большая часть правил (слои, прогоны, модель) от него не зависит.
* **Оформление под конкретного заказчика.** Палитра и подписи — предмет
  договорённости; правило только в том, что смысл цвета один на весь проект.
