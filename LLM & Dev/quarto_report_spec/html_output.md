# Вывод в HTML: таблицы и два графических стека

Автоматически отображается только последнее выражение ячейки, а из ветви `if`
не отображается вовсе. **Весь вывод — через явный `show()`.**

**Однородность обязательна.** Один табличный движок на длинные витрины, один
на короткие. Графический — **один на отчёт**: ECharts **или** Plotly, не оба.
Смешивать нельзя: читатель считает разное оформление разным смыслом.

## 1. Что чем

| что показать | чем | зачем |
|---|---|---|
| длинная витрина, поиск, сортировка | `reactable` | больше 10–15 строк |
| короткая сводка, фиксированная выборка | `great_tables` | читается целиком |
| категории, доли, суммы по оси | **ECharts** | полоса, круг; ось от нуля |
| распределение, overlay, log, иерархия | **Plotly** | жанр, который ECharts не выражает |
| сила вывода и легенда | карточки и легенда разметкой | смысл с одного взгляда |

Таблицы одинаковы в обоих стеках. Расходится только графический движок.

## 2. Выбор стека — по жанру, не по привычке

| жанр | стек | признак жанра |
|---|---|---|
| сумма или доля по категории | ECharts | у оси конечный перечень имён |
| ступень, причина, состояние | ECharts | перечень приходит из модели |
| bins, плотность, хвост | Plotly | величина непрерывна, категорий нет |
| наложение двух-трёх выборок | Plotly | сравниваются формы, `barmode="overlay"` |
| логарифмическая ось | Plotly | разброс на порядки |
| иерархия (`ids`/`parents`/`values`) | Plotly | icicle, treemap, sunburst |

**Не выбирать Plotly, если хватает ECharts.** Второй движок заводится под жанр,
а не «на всякий случай».

**Стек выбирается при создании отчёта и не меняется внутри него.** Перевод
готового отчёта на второй стек — переписывание всех его графиков, а не
добавление одного: у движков разная сериализация, разные подписи и разный
обработчик размера (раздел 7).

**Зависимость не заводится раньше отчёта, который её потребляет.**

## 3. Контракт подключения — общий на оба стека

`inject_css(engine=…)` вызывается из setup-чанка, не из шапки `.qmd`.
Порядок обязателен и не изобретается заново в каждом отчёте:

1. CSS таблиц и правила ширины;
2. **один** вендоренный JS — `echarts.min.js` *или* `plotly.min.js` — со снятием
   `define` на время загрузки и скрытым якорем рядом;
3. витрина — `reactable.to_widget(...)`; график — `div` + короткий init,
   без megascript в ячейке с `#| label: fig-…`.

**Движок — параметр `inject_css()`, а не константа библиотеки.** Пока
библиотека жёстко эмитит один вендор, правило «один движок на отчёт» записано,
но неисполнимо: отчёт физически не может выбрать второй.

**Второй вызов с другим движком — исключение, а не второй `<script>`.**
Библиотека держит множество уже выданных вендоров и падает с именем движка.
Правило, за которым нет исполнителя, — намерение.

### Четыре наблюдения, из которых вырос порядок

* **Quarto грузит RequireJS.** UMD-сборка, видящая `define`, уходит в AMD:
  глобал не появляется, canvas пустой, **ошибки нет**. `include-in-header`
  с `<script src="…">` падает в ту же яму, а отдельный header-файл ещё и бьётся
  об игнор `*.html` в репозитории. Наблюдение относится к ECharts; про Plotly —
  раздел 5.
* **Ячейка с `#| label: fig-…` оборачивается в `<figure>`**, и Quarto вырезает
  огромный `<script>`. Короткий init остаётся, библиотека — нет. Отсюда:
  библиотека эмитится один раз из setup, в ячейке графика только init.
* **Вывод ячейки из одних `<script>` пропадает.** CSS из той же setup-ячейки
  доезжает. Рядом с megascript нужен якорный элемент — иначе setup молча
  теряется целиком.
* **Сырой `Reactable` без `to_widget` и без CSS из setup** даёт пустую заглушку
  `widget-view`. Снятие `window.define` без этих двух шагов чинит графики
  и глушит витрины: менеджер виджетов уже прочитал состояние.

Обёртка с локальными `var define, module, exports` вокруг вендора **не замена**
снятию `define`. Не изобретать третий способ.

## 4. ECharts — стек A

Собрать `options: dict`, отдать в `echarts.init(el).setOption(options)`.

| приём | как | почему |
|---|---|---|
| данные | Polars `.to_list()` | движок читает только JSON-массивы, бинарного входа нет |
| функции в опциях | маркер-подстановка после `json.dumps` | форматтер оси обязан остаться функцией, а не строкой |
| `</script>` в данных | ручная замена `<` на `\u003c` | `json.dumps` этого не делает, а подписи иногда несут теги |
| повторный boot | `getInstanceByDom(el) \|\| init(el)` | второй `init` на том же div даёт две канвы |
| размер окна | свой обработчик `resize` → `inst.resize()` | автоматики у движка нет |
| ось величин | `min: 0` | иначе при близких крупных суммах шкала обрезается и сравнение полос искажается |
| разряды | `toLocaleString('ru-RU')` в форматтере | локали в бандле нет |

**Python-пакет не нужен.** `pyecharts` не ставится: опции — обычный `dict`
(его `dump_options` с этим совместим). Следствие: вендор лежит в репозитории
(`lab/lib/assets/echarts.min.js`, ~1 МБ) и обновляется руками — версия движка
ничем не связана с окружением и в манифест прогона не попадает. Это цена
отказа от пакета, и её надо знать.

## 5. Plotly — стек B

`go.Figure(...)` → `pio.to_json(fig)` → `Plotly.react(divId, data, layout, config)`.

**Вендор берётся из установленного пакета**, а не из CDN и не из npm:

```python
Path(plotly.__file__).parent / "package_data" / "plotly.min.js"
```

Основание не удобство: сериализатор и рендерер обязаны быть одной версии.
`pio.to_json` кодирует числовые массивы в base64 (`{"dtype":…,"bdata":…}`),
и бандл другой ветки прочитает такую фигуру пустым графиком без ошибки.

### Замер бандлов (колёса с PyPI, 2026-08-30)

| plotly.py | plotly.js | обёртка | `define.amd` | размер |
|---|---|---|---|---|
| 5.24.1 | 2.35.2 | webpack UMD | **есть** | 4,4 МБ |
| 6.8.0 | 3.6.0 | только `module.exports`, иначе `root`; `window.Plotly` присваивается внутри фабрики | нет | 4,8 МБ |
| 7.0.0 | 4.0.0 | та же | нет | 4,1 МБ |

**AMD-ловушки у Plotly ≥ 6 нет.** Снятие `define` в общем контракте для этого
стека избыточно и оставлено ради одного порядка на оба движка; в коде это
названо комментарием, а не выдано за необходимость. На 5.x ловушка настоящая —
вниз по версии контракт не переносится молча.

**Размер — единственная реальная цена стека.** 4,8 МБ против ~1 МБ, и при
`embed-resources: true` это вес каждого HTML. Довод в пользу раздела 2.

| приём | как | почему |
|---|---|---|
| сериализация | `pio.to_json(fig)` | `json.dumps(fig.to_plotly_json())` падает на `datetime` и `numpy` |
| `</script>` в данных | ничего не делать | `pio.to_json` сам экранирует `<` в `\u003c` и не-ASCII в `\uXXXX` |
| данные | Polars `.to_numpy()` | 2 000 точек: 33,7 КБ через `bdata` против 45,2 КБ списком |
| MathJax | `config={"typesetMath": False}` | публичный атрибут конфига (умолчание `true`); в plotly.js ≥ 3 `window.PlotlyConfig` не читается вовсе |
| тема | свой шаблон в `pio.templates`, объявленный в библиотеке | шаблон по умолчанию весит 7,2 КБ **на каждую фигуру** и рисует чужой палитрой; минимальный проектный — 70 байт |
| разряды | `layout.separators = ", "` | локали внутри бандла нет |
| размер окна | `config={"responsive": True}` | движок ставит обработчик сам; свой добавлять не нужно |
| повторный boot | `Plotly.react` | `newPlot` перерисовывает фигуру целиком |
| высота | `layout.height` | смешивать с CSS-высотой div не нужно: два источника размера расходятся |

**Патч приватного `plotly.io._html._window_plotly_config` не применяется.**
Он трогает атрибут, читаемый только `to_html`, и вписывает глобал, которого
в plotly.js ≥ 3 нет; через `plotly.io._html` он к тому же недоступен обычным
обращением — ленивый импортёр отдаёт `AttributeError`. Чужой отчёт, где такой
патч стоит, показывает **жанр** графика, а не способ сборки HTML.

## 6. Запрещено, и почему

| запрет | основание |
|---|---|
| `include_plotlyjs="cdn"` | отчёт с `embed-resources: true` уносят с машины без сети |
| `fig.show()` | зовёт браузерный renderer, в Quarto даёт пустоту или свой `<script>` мимо контракта |
| `to_html(full_html=True)` | документ даёт Quarto; второй `<html>` внутри страницы |
| патч приватного API движка | раздел 5 |
| два движка в одном `.qmd` | раздел 1 |
| megascript в ячейке `fig-…` | раздел 3, наблюдение второе |
| вендор из CDN или npm | раздел 5, расхождение версии с сериализатором |
| pandas перед графиком | оба стека принимают списки и numpy напрямую |
| числа в прозе | проза не пересчитывается |

## 7. Различия, которые обёртка не стирает

Общая обёртка (`bar()`, `pie()`, `hist()`, `tree()`) прячет движок от отчёта,
но не делает движки одинаковыми. Что расходится и обязано быть учтено
в библиотеке, а не в чанке:

| | ECharts | Plotly |
|---|---|---|
| вход данных | список | numpy |
| сериализация | свой дамп + экранирование | `pio.to_json` |
| функции в опциях | нужны (форматтеры) | не нужны (`texttemplate`) |
| тема | палитра в каждом option | шаблон один на документ |
| размер окна | вручную | `responsive` |
| идемпотентность | `getInstanceByDom` | `Plotly.react` |
| разряды | форматтер | `separators` |
| источник вендора | файл в репозитории | установленный пакет |
| вес | ~1 МБ | ~4,8 МБ |

## 8. Прочее по отчёту

**`_quarto.yml` не заводится.** Каждый `.qmd` самодостаточен: шапка целиком
внутри файла — так отчёт переносится и рендерится поодиночке.
`embed-resources: true`.

**Один HTML на объект.** Если сверка собирается по нескольким объектам,
имя выходного файла задаётся в шапке (`output-file`) либо файл переименовывается
сразу после рендера. Флаг `--output` вместе с `embed-resources` в ряде версий
Quarto падает.

**Пустая витрина показывается** заголовками и явной строкой «посчитана и пуста»,
а не исчезает: пустой раздел выглядит как отсутствие нарушений.

**Мокапы интерфейса рисуются разметкой в самом `.qmd`**, а не картинками: пока
контур обсуждается, стоимость правки важнее переносимости иллюстрации.

Рабочий скелет библиотеки с обоими стеками — `assets/lib/render.py`.
