# Разметка в шапках great_tables: позиция Posit и как с ней жить

Инструкция написана после прямого вопроса «в шапках таблиц синтаксис md не рендерится,
как чиним». Всё, что ниже, **проверено на месте** — исходники установленного пакета,
прогон строк через его же функции, документация Posit по R- и python-версии, — а не
пересказано по памяти. Версия: `great_tables` 0.24.0, python 3.13.

## Короткий ответ

Флага нет. Ни в python-версии, ни — для шапки — в R-версии.

Способ, который Posit документирует, один: обернуть текст в `md()` или `html()`
на месте вызова. Никакого «включить markdown для таблицы целиком» в API не существует,
и это не упущение сборки, а решение библиотеки: строка по умолчанию — текст, разметка
объявляется явно.

## Почему обычная строка не рендерится

`great_tables/_text.py`, функция `_process_text`, разводит два случая:

```python
def _process_text(x: str | BaseText | None, context: str = "html") -> str:
    if isinstance(x, str):
        return escape_fn(x)          # html.escape — и всё, markdown не разбирается
    elif isinstance(x, BaseText):
        return x.to_html()           # md() и html() — наследники BaseText
```

Обычная `str` уходит через `html.escape`. Дальше существенная тонкость: `html.escape`
экранирует `& < > " '` и **не трогает обратную кавычку**. Поэтому дефект выглядит не как
`&#96;`, а как сама кавычка на странице: markdown просто нигде не разбирался.

`md()` и `html()` — это `Md(Text)` и `Html(Text)`, наследники `BaseText`, у которых
`to_html()` вызывает commonmark. Тип аргумента и есть переключатель.

## Что проверено

| утверждение | как проверено | исход |
|---|---|---|
| у `GT()` есть аргумент `process_md` | `inspect.signature(GT.__init__)` на 0.24.0 | **нет**: `data, rowname_col, groupname_col, auto_align, id, locale` |
| в `tab_options()` есть ключ про markdown | поиск по исходнику метода | **нет** |
| `fmt_markdown()` решает задачу шапки | докстринг и сигнатура | **нет**: это форматтер `columns`, то есть ячеек данных |
| `md()` включает разметку в шапке | `_md_html("обход \`model/\`")` | `обход <code>model/</code>` |
| обычная строка экранируется без разбора | `_process_text("обход \`model/\`")` | `обход \`model/\`` — кавычки на странице |
| в R-версии `gt()` есть `process_md` | reference R-пакета | **есть**, но область — `rowname_col` и `groupname_col`, то есть боковик и подписи групп строк; шапки, подзаголовка и сноски он не касается |
| 0.24.0 что-то поменяла в разметке | release notes 0.24.0 | **нет**: `opt_interactive()` и три правки докстрингов |

Вывод про R стоит здесь не для полноты. Вопрос «а в R так было можно» возникает первым,
и ответ на него — «можно, но не для шапки»: тем же способом это чинилось бы и там.

## Какие методы принимают `md()`

Докстринги пакета называют их поимённо — везде формулировка одна («we can optionally use
the `md()` and `html()` helper functions»):

| метод | что печатает |
|---|---|
| `tab_header(title, subtitle)` | заголовок и подзаголовок таблицы |
| `tab_source_note(source_note)` | сноска под таблицей |
| `tab_spanner(label, …)` | надпись над группой колонок |
| `cols_label(**kwargs)` | подписи колонок |
| `tab_stubhead(label)` | шапка боковика |

## Как это пишется

Оборачивается **тот аргумент, в котором есть разметка**, а не вызов целиком:

```python
.tab_header("Каталог модели",
            md("строится обходом `model/`; перечень в тексте отчёта "
               "устарел бы первым же новым файлом"))
```

f-строка оборачивается так же — `md(f"источник: `{путь}`")`: разметку разбирает уже
готовая строка, и подстановка ей не мешает.

Заголовок без разметки остаётся обычной строкой. Оборачивать всё подряд «на всякий
случай» не нужно и вредно: `md()` — это commonmark целиком, и текст начинает жить по его
правилам. Парные `*` и `_`, квадратные скобки со скобкой следом, решётка в начале строки
получают значение, которого автор не имел в виду. Одиночные знаки безопасны, и путь
внутри обратных кавычек безопасен тоже — `form.*._editions` в кодовой врезке в курсив
не уезжает.

## Ловушка: дефект молчаливый

Сбоя нет. Таблица рисуется, отчёт собирается, тесты зелёные — неверна только вёрстка.
Заметить это можно единственным способом: глазами на собранном html. Ровно поэтому
разметка без `md()` живёт долго и тиражируется копированием соседней шапки.

Отсюда правило: у запрета «не писать разметку в шапке без `md()`» обязан быть
механический исполнитель. Образец ловится по AST и стоит десятка строк — метод из
известного набора, аргумент, в котором есть <code>`код`</code>, `**жирный**` или ссылка,
и сам аргумент не обёрнут в `md`/`html`:

```python
MD_METHODS = {"tab_header", "tab_source_note", "tab_spanner", "tab_stubhead", "cols_label"}
MARKUP = re.compile(r"`[^`]+`|\*\*[^*]+\*\*|\[[^\]]+\]\([^)]+\)")

if isinstance(n, ast.Call) and isinstance(n.func, ast.Attribute) \
   and n.func.attr in MD_METHODS:
    for arg in [*n.args, *(k.value for k in n.keywords)]:
        if isinstance(arg, ast.Call) and isinstance(arg.func, ast.Name) \
           and arg.func.id in {"md", "html"}:
            continue
        if MARKUP.search(ast.unparse(arg)):
            ...  # срабатывание
```

`ast.unparse` берёт на себя и неявную склейку строк (в дереве это уже одна константа),
и f-строку. Одиночные `*` и `_` в образец не входят намеренно: в русской прозе они
встречаются знаками, а не выделением, и ловить их значило бы топить находки в шуме.

## Что из этого общего

Три вещи, переносимые за пределы этой библиотеки.

**Тип аргумента как переключатель поведения.** Библиотека не заводит флаг «трактовать
текст как разметку», потому что флаг — состояние, а состояние расходится с текстом.
Обёртка `md(...)` стоит там же, где текст, и разойтись с ним не может.

**Умолчание в пользу текста.** Строка по умолчанию — данные, а не программа. Обратное
умолчание («всё считаем markdown») тихо переосмысливает знаки в прозе, которую никто
размечать не собирался, и цена ошибки падает на читателя.

**Молчаливый дефект требует исполнителя.** Ошибка, которая не роняет сборку и видна
только глазами, правилом в методичке не закрывается. Либо у правила есть механическая
проверка, либо правила нет.
