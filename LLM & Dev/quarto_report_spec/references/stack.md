# Стек

Python 3.13, `uv`, единое `.venv` в корне. Запуск скриптов и тестов — через
`uv run`, без зависимости от активированного окружения.

**`quarto render` — исключение.** Он стартует из PATH и не идёт через `uv run`:
без активированного `.venv` не находит `nbclient`. Перед полным рендером —
активировать окружение. Кнопка Render в IDE этим не страдает: ядро уже
привязано к `.venv`.

## Состав

| назначение | пакет | почему он, а не другой |
|---|---|---|
| обработка | **polars** | цепочки, векторизация, ленивые выражения |
| хранилище | **duckdb** + parquet | Arrow напрямую, без `to_pandas()` |
| чтение xlsx | **fastexcel** (calamine) | openpyxl бракует ячейку с битым serial даты и роняет чтение файла целиком; calamine отдаёт её сырым значением |
| сходство строк | **rapidfuzz** | на порядок быстрее `difflib`, терпит перестановку слов |
| таблицы длинные | **reactable** | сортировка, поиск, больше 10–15 строк |
| таблицы короткие | **great_tables** | фиксированные выборки, читается целиком |
| графики, стек A | **Apache ECharts** | категории и доли; option-dict, python-пакет не нужен |
| графики, стек B | **plotly** `>=6.8` | распределение, иерархия, overlay; вендор берётся из самого пакета |
| проверки данных | **pointblank** | декларативные ожидания вместо ассертов россыпью |
| Excel | **xlsxwriter** | `constant_memory` для больших листов |
| признаки из текста | **re** (стандартная библиотека) | словарь сущностей не заводится, пока хватает регулярки |
| PDF | **pdfplumber** | разбор с координатами |
| внешняя модель | **chatlas** + провайдер | единственный необязательный пакет |

**Необязательный пакет — ровно один класс зависимостей.** Его отсутствие
обрабатывается **достижимой** ветвью: без него недоступна одна функция,
а основной результат тот же. Недостижимая запасная ветвь хуже её отсутствия —
она обещает работу без зависимости, которой на деле нет.

**Новая зависимость добавляется через `uv add`** и объявляется в
`pyproject.toml` с комментарием «почему она», если выбор неочевиден.

**Зависимость не заводится раньше кода, который её потребляет.** Объявленный
и не подключённый пакет — та же недостижимая ветвь.

## Почему без pandas

pandas не является слоем обработки. Допустим только там, где задача без него
нерешаема, и переход локален и назван комментарием.

Основания, по убыванию веса:

1. **Два диалекта в одном репозитории — это два набора ловушек.** Индекс,
   выравнивание по индексу, `SettingWithCopyWarning`, `NaN` против `null`,
   молчаливое приведение типов при конкатенации. Смешанный код перестаёт
   читаться как один язык.
2. **Переход стоит копии.** `.to_pandas()` материализует и копирует; Polars
   и DuckDB обмениваются через Arrow без копии. На витринах в сотни тысяч
   строк это разница в разы, а не в процентах.
3. **Типы теряются.** Через pandas `Decimal`, `Date` и категориальные
   возвращаются не тем, чем ушли; расхождение всплывает не на переходе,
   а в итоге отчёта.
4. **Отсутствие pandas — проверяемое правило**, а «пользоваться им умеренно» —
   не проверяемое. `grep -rn "import pandas" lab/ <core_pkg>/` даёт ответ
   за секунду.

**Обходы вместо pandas:**

| соблазн | замена |
|---|---|
| `pd.read_excel` | `pl.read_excel(engine="calamine")` |
| `df.to_pandas()` перед DuckDB | зарегистрировать Arrow: `duckdb.sql("… FROM arrow_tbl")` |
| pandas перед графиком | оба стека берут списки или numpy напрямую |
| pandas ради `pivot_table` | `pl.DataFrame.pivot`, длинная форма как база |
| pandas ради стилей в Excel | `xlsxwriter` напрямую |

Если пакет всё же требует pandas на входе (редкий отчётный движок), переход
делается **в одной функции слоя вывода**, с комментарием, называющим пакет
и причину. Он не поднимается выше слоя вывода.

## Хранилище

Длинная форма — базовая таблица, широкая — представление. Колонки в DuckDB
латиницей; русские подписи — через таблицу локализации и вьюхи.

Parquet на прогон; DuckDB — на сквозные выборки между прогонами.
