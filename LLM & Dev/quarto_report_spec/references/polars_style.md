# Polars: идиоматика и ловушки

## Стиль

**Цепочки, векторизация, никаких построчных циклов.** `map_elements` — крайняя
мера; в комментарии рядом с ним должно стоять, почему выражением не вышло.

**`polars.selectors` вместо сравнения строк-типов.**

```python
import polars.selectors as cs
df.select(cs.numeric().fill_null(0), cs.string().str.strip_chars())
```

`dtype == "Float64"` ломается на первом же `Float32` и не ловится тестом.

**Имена колонок латиницей.** Русские подписи живут только на слое вывода:
`react(names=…)`, `gt(labels=…)`, `labs()`, заголовки листов Excel. Имя колонки
по-русски становится частью предметной модели и меняется вместе с формулировкой
в отчёте — то есть модель правится редактурой.

**Ленивость там, где есть фильтр и проекция.** `scan_parquet(...).filter(...)`
читает меньше, чем `read_parquet(...).filter(...)`. Для витрин прогона,
которые всё равно берутся целиком, разницы нет — не усложнять ради формы.

**Импорты на верхнем уровне.** В `.py` — после docstring, в `.qmd` —
в setup-чанке. Импорт внутри функции допустим только при циклической
зависимости и с комментарием.

**Закомментированный код не удаляется** без явной просьбы: это следы
исследования, а не мусор.

**Комментарий объясняет «почему», а не «что».** Хороший комментарий называет
наблюдение, из-за которого код написан именно так:

```python
# skip_nulls=False обязателен. С умолчанием Polars не вызывает функцию на null
# и кладёт null сразу: множитель null обнуляет всё количество строки.
```

## Ловушки, каждая из которых уже стоила прогона

**Регулярки без lookahead и lookbehind.** Движок (`regex` crate) их не
поддерживает. Не «работает медленно», а не компилируется. Переписать шаблон
или разбить на шаги: сначала извлечь кандидата, потом отфильтровать выражением.

**`group_by` не сохраняет порядок.** Он многопоточный; `with_row_index` после
него даёт разные идентификаторы от прогона к прогону, и диффы прогонов
становятся шумом. **Правило: сортировка, потом индекс.** Если порядок нужен
внутри агрегации — `maintain_order=True` явно, с комментарием о цене.

**`join` по неуникальному ключу — декартово произведение.** Наблюдения из
нескольких источников (правило, модель, согласие) обязаны быть свёрнуты
в дедуплицированный набор фактов **до** соединения, с колонкой-источником.
Иначе одна строка справочника размножает свидетельство в разы, и итог
выглядит правдоподобно.

**Порядок категорий на оси — `pl.Enum`, а не выражение внутри графика.**
Сортировка фрейма делается до вызова отрисовки.

```python
order = ["принято", "триаж", "отклонено"]
df = df.with_columns(pl.col("state").cast(pl.Enum(order))).sort("state")
```

**`null` и ноль различаются и должны различаться до самого вывода.** Ноль —
«посчитано, вышло ноль». `null` — «величина существует, но в этот итог не идёт»
либо «такого не бывает на этом наборе». `fill_null(0)` перед агрегацией стирает
это различие навсегда; делать это можно только на слое вывода и осознанно.

**Схема объявляется явно там, где фрейм пустой.** Пустой результат с выведенной
схемой теряет колонки, и следующий шаг падает не там, где сломалось.

**`concat` с разными схемами.** `how="diagonal"` дописывает `null`, `how="vertical"`
падает. Падение лучше: молчаливый `null` в ключевой колонке проходит все
дальнейшие шаги.

## Баланс между шагами

Каждый шаг конвейера отдаёт число строк до и после. Потеря строк без
объяснения — дефект, а не особенность данных.

```python
def balance(before: pl.DataFrame, after: pl.DataFrame, step: str) -> None:
    """Строки не исчезают молча: расхождение называет шаг и величину."""
    if before.height != after.height:
        raise ValueError(f"{step}: было {before.height}, стало {after.height}")
```

Там, где шаг обязан менять число строк (свёртка, разворот), баланс проверяет
не равенство, а объявленное соотношение.

## Переход в DuckDB

Через Arrow, без `.to_pandas()`:

```python
import duckdb
tbl = df.to_arrow()                      # zero-copy
duckdb.sql("SELECT * FROM tbl WHERE …")  # локальная переменная видна
```

Колонки в DuckDB латиницей; русские подписи — через таблицу локализации
и представления, а не переименованием базовых таблиц.
