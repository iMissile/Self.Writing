# Таблицы: разметка, разряды, развороты

Два табличных движка, и оба одинаковы в обоих графических стеках: `reactable`
на длинные витрины, `great_tables` на короткие. Здесь — то, что ломается
не в расчёте, а в подаче, и потому не роняет сборку.

Общая черта всех дефектов ниже: **сбоя нет.** Таблица рисуется, отчёт
собирается, тесты зелёные — неверна только вёрстка. Заметить можно единственным
способом: глазами на собранном HTML. Ровно поэтому каждому запрету здесь
полагается механический исполнитель.

---

## 1. Разметка в шапке `great_tables` требует `md()`

**Флага «трактовать текст как markdown» нет.** Ни в python-версии, ни — для
шапки — в R-версии. Способ один: обернуть тот аргумент, в котором есть разметка,
в `md()` или `html()`.

Почему так устроено: `_process_text` разводит два случая по **типу** аргумента.

```python
if isinstance(x, str):
    return escape_fn(x)      # html.escape — markdown не разбирается вовсе
elif isinstance(x, BaseText):
    return x.to_html()       # md() и html() — наследники BaseText
```

Тонкость, из-за которой дефект незаметен: `html.escape` экранирует `& < > " '`
и **не трогает обратную кавычку**. Поэтому на странице видно не `&#96;`, а саму
кавычку — выглядит как опечатка автора, а не как несработавшая разметка.

**Методы, принимающие `md()`:**

| метод | что печатает |
|---|---|
| `tab_header(title, subtitle)` | заголовок и подзаголовок |
| `tab_source_note(source_note)` | сноска под таблицей |
| `tab_spanner(label, …)` | надпись над группой колонок |
| `cols_label(**kwargs)` | подписи колонок |
| `tab_stubhead(label)` | шапка боковика |

Оборачивается **аргумент**, а не вызов:

```python
.tab_header("Каталог модели",
            md("строится обходом `model/`; перечень в тексте отчёта "
               "устарел бы первым же новым файлом"))
```

f-строка оборачивается так же: разметку разбирает уже готовая строка.

**Не оборачивать всё подряд.** `md()` — это commonmark целиком, и текст
начинает жить по его правилам: парные `*` и `_`, квадратные скобки со скобкой
следом, решётка в начале строки получают значение, которого автор не имел
в виду. Заголовок без разметки остаётся обычной строкой.

**Проверено на месте** (`great_tables` 0.24.0): аргумента `process_md`
у `GT()` нет, ключа в `tab_options()` нет, `fmt_markdown()` — форматтер ячеек
данных, а не шапки. В R-версии `process_md` есть, но область его — боковик
и подписи групп строк; шапки, подзаголовка и сноски он не касается.

### Исполнитель

Образец ловится по AST и стоит десятка строк: метод из известного набора,
аргумент с разметкой, аргумент не обёрнут.

```python
MD_METHODS = {"tab_header", "tab_source_note", "tab_spanner",
              "tab_stubhead", "cols_label"}
MARKUP = re.compile(r"`[^`]+`|\*\*[^*]+\*\*|\[[^\]]+\]\([^)]+\)")

if isinstance(n, ast.Call) and isinstance(n.func, ast.Attribute) \
   and n.func.attr in MD_METHODS:
    for arg in [*n.args, *(k.value for k in n.keywords)]:
        if isinstance(arg, ast.Call) and isinstance(arg.func, ast.Name) \
           and arg.func.id in {"md", "html"}:
            continue
        if MARKUP.search(ast.unparse(arg)):
            ...  # срабатывание
```

`ast.unparse` берёт на себя и неявную склейку строк, и f-строку. Одиночные `*`
и `_` в образец не входят намеренно: в русской прозе они встречаются знаками,
а не выделением, и ловить их значило бы топить находки в шуме.

## 2. Развороты строк: вложенные таблицы

Плоская таблица на дюжину колонок заставляет читателя держать связь глазом.
Разворот строки решает ту же задачу иначе: снаружи — итог и **где оборвалось**,
внутри — состав.

**Когда разворот, а когда свёртка.** Это разные механизмы, и путать их дорого:

| задача | механизм |
|---|---|
| первая колонка повторяется десятками строк | `group_by` — свёртка, ни одна строка не пропадает |
| у строки есть **состав другой природы** | разворот `details` — дочерняя таблица со своей схемой |
| надо и то, и другое | свёртка снаружи, разворот внутри строки не сочетаются: выбрать одно |

Свёртка — представление одних и тех же строк. Разворот — вторая таблица
с другими колонками. Итог с ярлыком «агрегатом» не объясняет ничего; объясняет
разложение, и его место — в развороте.

### Ловушка первая: `row_index` локален для виджета

Колбэк `details` получает `RowInfo`, у которого `row_index` отсчитывается
**внутри своего виджета**. Один глобальный колбэк на несколько таблиц (вкладки,
разрезы, страницы) будет брать ключ из чужого кадра и молча выдавать чужой
состав.

Отсюда: колбэк создаётся **фабрикой-замыканием на конкретную пару кадров**.

```python
def _details_for(outer, child):
    def _d(ri: RowInfo):
        key = outer.get_column(key_col).to_list()[ri.row_index]
        sub = child.filter(pl.col(child_key) == key)
        ...
    return _d
```

Ключ разворота — **отдельная колонка**, а не номер строки. Номер позиции внутри
документа для этого не годится: он повторяется от документа к документу.
Составной ключ собирается явно и прячется из показа.

```python
outer = outer.with_columns(_key=pl.format("{}#{}", pl.col("act"), pl.col("item")))
```

### Ловушка вторая: верхний ряд шапки у разворотов

Обёртка вложенных таблиц легко теряет `column_groups`: параметр просто не
передаётся во внешний виджет. Плоская таблица с двумя группами шапки, переведённая
на развороты, теряет их молча — и дюжина колонок снова читается одним рядом цифр.
Параметр обязан быть у **обеих** таблиц, внешней и дочерней.

### Ловушка третья: дым этого не проверяет

Обёртка разворотов в дымовом прогоне заглушена (иначе чанк тянет браузерный
рантайм). Отчёт с разворотами проверяется полным рендером — см.
`references/tooling.md`, «Чего дымовой рендер не видит».

### Ловушка четвёртая: состав добывается колонкой, а не пересчётом

Чтобы показать, из чего сложился итог, нужен состав. Соблазн — восстановить его
в отчёте по тому же правилу, по которому его считала библиотека. Это заводит
**вторую реализацию правила**, и расходится она молча.

Правильный ход: библиотека **возвращает состав колонкой**. Ключ группы, перечень
слагаемых, признак способа сцепки — всё, что отчёту нужно показать, отдаётся
оттуда, где считалось.

Колонка объявляется **всегда**, даже когда механизм не сработал ни разу: схема
витрины, зависящая от данных, ломает и снимок, и потребителя — разворот не может
то быть, то исчезать от прогона к прогону.

### Что показывать в развороте

Разворот отвечает на вопрос «из чего это сложилось», и потому в нём:

* по строке на каждое слагаемое, с названием документа и величиной;
* **итоговая строка** набора — сумма, которая сравнивалась;
* обе стороны сверки **рядом с порогом**. Без порога число отклонения
  не читается: невозможно сказать, промах это на волос или в разы;
* у неподтверждённой строки — **пул, с которым сравнивали**. Иначе
  «не подтверждено» неотличимо от «не с чем было сравнивать», а это разные
  вещи: первое предъявляют, второе — пробел разбора.

### Ловушка пятая: тройная ограда рвёт чанк

Строка с тремя обратными кавычками внутри python-чанка обрывает сам чанк:
сборщик читает её как закрывающую ограду. Возникает при выводе промпта, лога
или фрагмента кода через `Markdown(...)`.

```python
F = chr(96) * 3      # ограда собирается из символа, а не пишется literal
display(Markdown(f"**Промпт:**\n\n{F}\n{text}\n{F}"))
```

Тот же приём нужен при снятии ограды с ответа модели.

## 3. Цвет строки обязан иметь легенду

Цвет — не украшение и не оценка. Он называет **род исхода**, и родов обычно
больше двух. Умолчание в `row_colors` («всё прочее — охра») накрывает разом
несколько разных случаев, и они читаются как один.

Правило: у каждой цветной таблицы под ней стоит врезка «что означает цвет»,
и в ней **столько строк, сколько цветов**, включая умолчание — с перечислением
того, что в него попадает.

Разводить обязательно два рода:

* цвет находки — то, что предъявляют контрагенту;
* цвет нерешённого — то, что адресуют методологу.

Слив их в один читается как обвинение там, где его нет.

**Рядом с легендой — «что уходит дальше».** Витрина редко конечна; чаще она
вход двух-трёх следующих глав. Поимённый перечень потребителей отвечает на
вопрос «где это потом используем» один раз и в одном месте.

## 4. Ширины и скролл

Горизонтального скролла быть не должно. Ширина считается по **содержимому**,
а не по имени колонки: колонка с текстом на 400 знаков и колонка с числом
не могут иметь одну ширину.

Приёмы, которые держат это без ручной подгонки:

* длина колонки — **90-й процентиль**, а не максимум: одна аномальная ячейка
  иначе забирает половину таблицы;
* сжатие корнем, пол по заголовку, несколько итераций перераспределения остатка;
* если сумма нужных ширин не влезает в тело — переход на **проценты**: сумма
  долей сходится по построению, и скролл становится невозможен;
* коды с дефисами и числа — `nowrap`: иначе `2.22181` ломается посередине;
* при `table-layout: fixed` подпись группы шире своей единственной колонки —
  ширину считать по подписи группы.
