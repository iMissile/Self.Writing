# Прогоны, манифест, кэши

Отчёт читает **датированный прогон**, а не «последнее, что лежало в памяти».

## Устройство каталога

```
lab/_artifacts/<ГГГГ-ММ-ДД_ЧЧММ>__<объект>/
├── run_manifest.json      паспорт: пороги, профили, счётчики, метрики
├── *.parquet              витрины конвейера и сверки
├── <книга>.xlsx           выгрузки для человека
└── llm_cache.json         снимок кэша внешних вызовов (если были)
```

**Имя каталога — момент расчёта и объект.** Без объекта в имени прогоны
разных наборов сравниваются между собой и дают разность по всем показателям
сразу — такая разность не говорит о правке ничего.

## Правила

**Прогоны не перезаписываются.** Без истории вопрос «что изменилось после
правки» отвечается по памяти, а это не ответ.

**Пустая витрина пишется файлом** с объявленной схемой, а её имя попадает
в `artifacts_empty` манифеста. Отсутствие файла неотличимо от «эту витрину
не считали» — а это разные вещи, и вторая означает сломанный конвейер.

**Две витрины с одним именем в одном прогоне запрещены.** Сохранение идёт
в общий каталог, и второй отчёт затрёт первый молча.

**Второй отчёт дописывает манифест**, не затирая чужое. Пустое значение
не затирает заполненное: иначе повторный запуск лёгкого отчёта обнуляет
метрики тяжёлого.

**Сравнение прогонов — инструментом, а не глазами.** Пока сравнение делается
по двум окнам, оно делается по памяти.

## Манифест

Минимальный состав:

```json
{
  "run_id": "2026-08-30_1412__object_a",
  "started_at": "…", "finished_at": "…",
  "object": "object_a",
  "code_version": "<git sha или dirty>",
  "model_files": {"checks.json": "<sha256>", "units.json": "<sha256>"},
  "thresholds": {"price_tolerance": 0.01, "name_similarity": 92},
  "counters": {"rows_in": 12043, "rows_matched": 9310},
  "metrics": {"share_matched": 0.773},
  "artifacts": ["pipeline.parquet", "recon.parquet"],
  "artifacts_empty": ["disputes.parquet"],
  "warnings": []
}
```

**Пороги обязаны быть в манифесте.** Вопрос «при каких порогах получены эти
цифры» отвечается по файлу. Хэши файлов модели — там же: иначе прогон
воспроизводим только вместе с рабочей копией.

**Каждое «не удалось проверить» называет, чего не хватило.** Честный журнал
показывает, что произошло на самом деле; молчание превращает несделанную
проверку в отсутствие нарушений.

**«Проверка не выполнена» и «нарушений нет» — категорически разные исходы.**
Они не сливаются ни в одной витрине, ни в одном итоге, ни в одном цвете.

## Кэши

| кэш | где | ключ | когда обесценивается |
|---|---|---|---|
| ответы внешней модели | `lab/_cache/llm_cache.json` | `PROMPT_VERSION\|модель\|левое\|правое` | при смене промпта или нормализации входа |
| снимок кэша прогона | `<прогон>/llm_cache.json` | — | никогда: часть паспорта |

**Правка промпта обязана сопровождаться сменой `PROMPT_VERSION`.** Иначе
старые ответы раздаются на новые вопросы — молча и правдоподобно.

**Кэш работает и без ключа доступа к модели.** Прогон, все ключи которого
в нём есть, воспроизводится без единого внешнего вызова. Отсутствующий ключ
не молчит — он попадает в журнал отдельным исходом, а не подменяется
умолчанием.

**Кэш накапливается между прогонами.** Повторный запуск идёт без вызовов вовсе.

## Порядок снятия нагрузки на внешнюю модель

Обращение к модели — последнее средство, а не первое. Стоимость — свойство
протокола, а не количества вопросов:

1. локальный вердикт по признакам;
2. кэш;
3. дедупликация уникальных пар;
4. пачки по два десятка;
5. **новый чат на каждую пачку**.

Повторный вызов на одном объекте без очистки истории увозит в следующую пачку
токены и суждение предыдущей — это и деньги, и чужое мнение, подмешанное
в ответ. Поштучные вызовы стоят на порядок дороже пачек при том же результате.

**Мнение модели не является документом.** Ни одно решение не принимается
автоматически по её ответу: он помечает, но не снимает и не назначает.
