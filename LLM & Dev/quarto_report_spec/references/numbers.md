# Формат числа: один на весь отчёт

Число в отчёте читают глазами и переносят в заключение руками. Поэтому вид
числа — не оформление, а часть утверждения: разряды, разделённые по-разному
в соседних таблицах, читаются как разные величины.

**Правило одно: число печатается общим хелпером.** Ни одного `f"{x:,.0f}"`,
ни одного `str(round(...))` в чанке отчёта.

---

## Канон

| элемент | что ставим | почему не иначе |
|---|---|---|
| разрядный разделитель | **неразрывный пробел** ` ` | обычный пробел переносит хвост числа на следующую строку; запятая занята десятичной точкой в англоязычной традиции и путает; апостроф и точка читаются как часть числа |
| десятичная точка | **точка** `.` | запятая как десятичная в паре с пробелом-разрядом даёт «1 234,5», где оба знака конкурируют за роль; точка однозначна и совпадает с тем, что печатает Polars и что кладётся в CSV |
| знак минус | обычный дефис-минус | типографский `−` ломает копирование числа в калькулятор |
| пусто | `—` | не ноль: «величина не наблюдалась» и «ноль» — разные утверждения |

Пара «неразрывный пробел + точка» выбрана ради **однозначности**: ни один
из двух знаков не может быть принят за другой. Это отступление от ГОСТ, где
десятичная — запятая, и отступление объявляется вслух, а не делается молча.
Если проект обязан следовать ГОСТ, меняется **хелпер**, а не отдельные вызовы.

---

## Мантисса: чем короче, тем правдивее

Число с плавающей точкой после деления несёт пыль: `0.0005845354875937403`.
Напечатанное как есть, оно раздувает колонку до двадцати знаков и — хуже —
**обещает точность, которой в измерении нет**.

Два правила:

**Разрядность объявляется родом величины, а не подбирается.** Натура — четыре
знака, деньги — два, доли — проценты без дробной части. Разрядность в вызове —
это решение, и оно повторяется в двадцати местах по-разному.

**Хвостовые нули режутся, но только когда колонка их не сравнивает.**
«90.9000 м» рядом с «90.0096 м» читается как разная точность измерения, хотя
это одна и та же величина в одной единице. Отсюда переключатель у хелпера:

```python
nfmt(90.9, 4)                          # "90.9000" — колонка сравнивается
nfmt(90.9, 4, drop_trailing_zeros=True)  # "90.9"   — величина стоит одна
```

Умолчание — **не резать**: в таблице чаще сравнивают, чем читают поштучно.

## Скелет хелпера

```python
NBSP = " "

def nfmt(x, dec: int = 0, *, drop_trailing_zeros: bool = False) -> str:
    """Число человеку: разряды неразрывным пробелом, десятичная точка — точка.

    Пусто печатается прочерком, а не нулём: «величина не наблюдалась»
    и «ноль» — разные утверждения, и подменять первое вторым запрещено.
    """
    if x is None:
        return "—"
    s = f"{float(x):,.{dec}f}"                 # разряды запятой, точка десятичная
    whole, _, frac = s.partition(".")
    whole = whole.replace(",", NBSP)           # только в целой части
    if frac and drop_trailing_zeros:
        frac = frac.rstrip("0")
    return f"{whole}.{frac}" if frac else whole
```

Ключевое здесь — **замена только в целой части**. Разбор `partition(".")`
не украшение: см. ловушку ниже.

## Ловушка: замена по всей строке съедает запятые прозы

Самый частый способ получить неразрывный пробел — отформатировать `f"{x:,.0f}"`
и заменить запятые. Если замена применяется **ко всей собранной строке**,
а не к числу, вместе с разрядами исчезают запятые русского текста.

```python
# было — и в собранном HTML читалось «по накладной  а не объём выполненного»
display(Markdown(
    f"Из {own:,.0f} ₽ материалы {mat:,.0f} ₽ — их подтверждает баланс, "
    f"а не объём выполненного.".replace(",", " ")))
```

Дефект молчаливый: сборка проходит, число выглядит правильно, а проза теряет
пунктуацию — и заметно это только чтением абзаца целиком на собранной странице.

Правильно — форматировать **число**, а не абзац:

```python
display(Markdown(f"Из {nfmt(own)} ₽ материалы {nfmt(mat)} ₽ — их подтверждает "
                 f"баланс, а не объём выполненного."))
```

Отсюда общее: **преобразование, которое должно коснуться части строки, никогда
не применяется к строке целиком.**

## Где формат задаётся, если печатает не наш код

Табличные и графические движки форматируют числа сами, и их надо настроить —
одним местом на отчёт, а не в каждом вызове.

| движок | чем задаётся |
|---|---|
| `great_tables` | `fmt_number(..., sep_mark=" ", dec_mark=".")` в обёртке-хелпере |
| `reactable` | форматтер колонки в общей библиотеке отрисовки |
| ECharts | форматтер оси и подсказки; локали в бандле нет |
| Plotly | `layout.separators = ". "` — первый знак десятичный, второй разрядный |

**У `great_tables` есть ловушка порядка.** Общий числовой форматтер, применённый
последним, переопределяет формат колонок, которые ему передали. Дробную колонку
ему передавать нельзя: расход `0.0112` печатается как `0`, а натура `83.767` —
как `84`. Форматтер вызывается **до** частных `fmt_number` либо получает только
целочисленные колонки.

## Исполнитель

Запрет ловится по AST: форматная спецификация с разрядной запятой либо вызов
`round()` прямо в аргументе вывода.

```python
FMT_SPEC = re.compile(r":\s*[,_].*[fd]")          # {x:,.0f} и родня

for n in ast.walk(tree):
    if isinstance(n, ast.FormattedValue) and n.format_spec is not None:
        if FMT_SPEC.search(ast.unparse(n.format_spec)):
            ...  # срабатывание: число печатается мимо общего форматтера
```

Срабатывание имеет ровно три исхода, и молчаливого среди них нет: правка,
строка `# обосновано: <почему>` или принятие базой после разбора.

## Что это правило не решает

**Единицу измерения.** Число без единицы — не величина. Единица приходит из
реестра параметров и печатается рядом; хелпер числа её не знает и знать не должен.

**Приведение к канону.** Формат — это подача. Если величина хранится в
килограммах, а печатается в тоннах, это **преобразование**, и место ему в слое
расчёта с объявленным переходом, а не в форматтере. Смешение этих двух вещей
даёт род ошибки «величина разошлась с подписью»: 5633.85 кг, напечатанные как
«т», уезжают в заключение заказчику.
