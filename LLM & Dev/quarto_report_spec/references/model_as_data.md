# Модель как данные, а не как код

Предметный слой — набор JSON в `lab/model/`. Каждый файл объявляет **знание**,
а не настройку.

## Типовой состав

| файл | объявляет | меняется при |
|---|---|---|
| `sources.json` | объекты, пути, профили, замер прототипа | смене состава набора |
| `schema.<вид>.json` | профили колонок источника | новом виде выгрузки |
| `dialects.json` | варианты написания ссылок и ключей | новом объекте с иным написанием |
| `units.json` | канон измерителей и приведения | новом измерителе |
| `ladder.json` | ступени сцепки, их сила, причины отсутствия пары | смене методики |
| `checks.json` | реестр проверок, направление находки | смене методики |

Состав проектный; неизменны требования к **полям** объявления.

## Обязательные поля объявления

**`why` — не «что делает», а «почему так».** Наблюдение, замер или решение
методолога. Объявление без основания неотличимо от настройки, подобранной
под данные, и первый же спор о нём выигрывает тот, кто громче.

**`measured` — замер рядом с объявлением**, с числами и датой:

```json
"measured": {"pairs": 77, "hit": 76, "share": 0.987, "date": "2026-08-28"}
```

**`status` — гипотеза объявлена гипотезой.** Значение «не подтверждена»
и сила «триаж». Поднять силу можно только новым замером, и он записывается
рядом. Гипотеза без метки живёт как факт ровно до первого спора.

## Правила проверки объявлений

**Гипотеза проверяется независимым ключом.** Соответствие калибруется на парах,
сцепленных **другими** основаниями — теми, которые о проверяемом признаке
ничего не знают. Проверять соответствие, сцепляя по нему же, значит ходить
по кругу и получать высокую долю согласия ни о чём.

**Локальное правило калибруется против уже полученных ответов эталона.**
Готовый разбор — эталон, за который уже заплачено. Правило, придуманное без
такого сравнения, неотличимо от правила, работающего хуже монетки: две ветви
фильтра могут выглядеть одинаково разумно, а дать 97 % и 41 % согласия.
Планка объявляется числом, а не словом «высокая».

**Порог не заменяет ключа.** Там, где различие сидит в одном символе внутри
длинного артикула, расстояние между строками бессильно по устройству.
Расширять зону уверенного вердикта поднятием порога нельзя: вместе с верными
парами поднимаются заведомо ложные, и замер это показывает.

**Дефект записи не есть признак предмета.** Обрезка поля выгрузки, гомоглиф,
артефакт переноса строки, пробел внутри номера — свойства записи. Они
снимаются нормализацией и ступенью, а не выносятся во внешний арбитраж:
ответ на такой вопрос — квитанция за собственный дефект, а не знание.

## Самопроверка модели

**Проверка категориальная, а не поштучная.** Новая категория останавливает
сборку, новый экземпляр внутри существующей категории — нет. Иначе
самопроверка либо не ловит дрейф конфигурации, либо падает на каждой строке
новых данных.

**Валидатор ловит:**

* противоречия внутри модели;
* расхождение модели с кодом (объявлено в JSON, не используется, и наоборот);
* необъявленное направление находки;
* нарушенный порядок ступеней;
* объявление без `why`.

**Инструмент проверяет образец, а не смысл.** Пройденный валидатор означает,
что модель не противоречит себе, — не что методика верна.

## Технический долг объявляется

Литерал, оставшийся в коде вместо модели, объявляется в таблице самопроверки
отчёта как долг с датой. Невидимый долг не возвращают.
